Accueil (Home)

L'application web locale Streamlit BacLipidAPP est développée afin d'interagir de différentes manières avec la base de données relationnelle SQLite BacLipidDB.

Le lancement de l'application permet à l'utilisateur d'arriver sur la page d'accueil (Home). Cette dernière affiche les cinq modules disponibles. Pour accéder à un module, il est possible de cliquer sur son nom dans la barre de navigation latérale à gauche de l'écran, ou directement sur son encadré depuis la page d'accueil.

Les statistiques affichées en dessous présentent le nombre de spectres MS1 et MS2 présents dans la base, ainsi que la taille de BacLipidDB sur le disque.

Module 1 : Intégration

La page Integration est un module permettant l'insertion de données dans BacLipidDB. L'intégration se déroule en cinq étapes.

1ère étape : Paramétrages (Step 1 - Settings)

La première étape demande à l'utilisateur de choisir le type de spectres qu'il souhaite insérer, ensuite le mode d'acquisition, son identité et enfin le nom du fichier (raw) d'origine des annotations. Ces paramètres seront réutilisés ultérieurement.

Annotation level MS1 / MS2 MS1 pour les annotations comportant uniquement l'ion analysé, MS2 pour les annotations d'un ion précurseur avec son spectre de fragmentation.
Ionization mode Positive / Negative Mode d'ionisation utilisé lors de l'acquisition. Sert uniquement à remplir le champ Ionisation_mode dans la base de données.
Your name Texte libre Nom de la personne qui intègre ce lot de données, enregistré dans l'historique d'import.
File row name Texte libre Nom du fichier brut (raw) de l'expérience à l'origine des annotations.

Il est impératif de compléter correctement les champs "Your name" et "File row name" afin de maintenir des données cohérentes et traçables dans le temps. Privilégier le caractère "_" pour séparer les mots et éviter les caractères spéciaux. Pour "Your name" la manière recommandée est Prénom_NOM. Pour "File row name", reprendre le nom du fichier brut (raw) tel quel, en remplaçant les espaces et caractères spéciaux par "_".

2ème étape : Chargement du fichier (Step 2 - File upload)

La seconde étape est le chargement du fichier. Il faut faire bien attention au format selon si vous avez sélectionné MS1 ou MS2 lors de l'étape 1. Pour un fichier de données MS1 le format attendu est .csv, .tsv ou .xlsx. Pour un fichier de données MS2 le format attendu est .csv ou .tsv. Si un fichier .xlsx est chargé, ce dernier sera rejeté et il faudra le convertir dans l'un des deux formats souhaités.

Le fichier doit répondre en tout point aux modèles du module 4. Il est bien évidemment possible à l'utilisateur de créer lui-même son fichier s'il ne souhaite pas télécharger les modèles (template), cependant l'introduction d'erreur peut nuire à l'intégration des données ensuite. Les points importants à prendre en compte sont le nommage des colonnes, la manière dont sont écrites les données et les champs obligatoires (cf. Module 4).

Le fichier chargé doit être nommé sous la forme Annotation_MS1/MS2_organisme_appareil. La date du jour n'est pas à inclure dans le nom du fichier, car elle est déjà gérée par l'historique d'import. Par exemple : Annotation_MS1_A.baumannii_MALDI_FTICR.xlsx, Annotation_MS2_A.baumannii_LC_MS.csv.

.csv .tsv .xlsx
Niveau annotation MS1MS2 MS1MS2 MS1
Description Fichier texte simple, valeurs séparées par des virgules. Lisible et modifiable avec un tableur ou un simple éditeur de texte. Fichier texte simple, valeurs séparées par des tabulations. À privilégier si vos données contiennent elles-mêmes des virgules. Fichier Excel natif (format binaire).

Pour un fichier MS1 : Une fois le fichier déposé, l'application vérifie simplement qu'il peut être lu correctement. Si la lecture réussit, un message de confirmation s'affiche : "File loaded : nom_du_fichier - X rows detected.". Si la lecture échoue, un message d'erreur "Error loading file : ..." s'affiche à la place. Il faudra résoudre cette erreur avant de le recharger.

Pour un fichier MS2 : Une fois le fichier déposé et chaque scan analysé avec succès, un message de confirmation s'affiche : "File loaded : nom_du_fichier - X scans detected.". Si l'analyse échoue, un message d'erreur "Error loading file : ..." s'affiche à la place. Ce message inclut toujours le détail précis du scan concerné et de la cause de l'erreur. Selon le problème rencontré dans le fichier, le texte affiché est l'un des suivants :

Cause Message affiché
Aucun scan trouvé dans le fichier "Error loading file : No scan found in the file."
Champ obligatoire manquant dans un scan "Error loading file : Missing field(s) for scan 'Scan #2183': Adduct."
Valeur non numérique (Precursor_MZ, Num_peaks, RT ou CCS) "Error loading file : Invalid Precursor_MZ for scan 'Scan #2183': 'abc'."
"Error loading file : Invalid Num_peaks for scan 'Scan #2183': 'abc'."
"Error loading file : Invalid RT for scan 'Scan #2183': 'abc'."
"Error loading file : Invalid CCS for scan 'Scan #2183': 'abc'."
En-tête m/z / Intensity manquant après les champs d'un scan "Error loading file : 'm/z' / 'Intensity' header expected for scan 'Scan #2183'."
Ligne de fragment incomplète (une seule colonne au lieu de deux) "Error loading file : Malformed fragment row ['85.5'] for scan 'Scan #2183': expected 'm/z' and 'Intensity' columns."
Ligne de fragment non numérique "Error loading file : Invalid fragment row ['abc', '1000'] for scan 'Scan #2183': 'm/z' and 'Intensity' must be numeric."
Aucun fragment trouvé pour un scan "Error loading file : No fragments found for 'Scan #2183'."
Le nombre de fragments ne correspond pas à Num_peaks "Error loading file : 'Num_peaks'=6 does not match the number of fragments found (5) for 'Scan #2183'."

Peu importe l'erreur, il faut corriger le scan concerné directement dans le fichier source, puis recharger le fichier.

3ème étape : Vérification des colonnes obligatoires (Step 3 - Required columns verification)

Le fichier MS1 est vérifié en 3 étapes successives. Dès qu'une vérification échoue, un message d'erreur s'affiche, le fichier doit être corrigé puis rechargé avant que la vérification suivante ne s'exécute. Si le fichier est conforme, il s'affiche avec le message "All required columns found".

# Cause Message affiché Comment corriger
1 Une ou plusieurs colonnes obligatoires absentes du fichier "The file is missing the following required columns : ..." Ajouter la/les colonne(s) manquante(s) (voir le guide des colonnes, module Resources)
2 Lipid_Name, Formula, Precursor_MZ ou Adduct contient une cellule vide ="The file contains empty cells in required columns : ..." Remplir les cellules vides de ces colonnes
3 Une valeur non numérique dans Precursor_MZ (texte, cellule mal formatée...) "The column Precursor_MZ must contain only numeric values..." Corriger la/les ligne(s) indiquée(s) pour n'avoir que des nombres

Pour un fichier MS2, le fichier ayant déjà été entièrement vérifié à l'étape précédente, cette étape ne fait qu'afficher un récapitulatif : le message "N scan(s) parsed successfully" ainsi qu'un encadré déroulant ("Preview scan data") reprenant le contenu de chaque scan, pour une dernière relecture avant de passer à l'étape suivante.

4ème étape : Complétion automatique et validation (Step 4 - Preview and automatic completion)

Certains champs prévus par le modèle (cf. Module 4) n'ont pas besoin d'être renseignés dans le fichier source car ils peuvent être calculés automatiquement à partir des colonnes Formula, Precursor_MZ et Adduct, ainsi que des paramètres choisis à l'étape 1. Un clic sur le bouton "Run automatic completion" lance ce calcul.

Colonne calculée Calculée à partir de Détails
Molecular_weight Formula La masse moléculaire moyenne est calculée à partir de la formule chimique.
Monoisotopic_mass Formula La masse monoisotopique exacte est calculée à partir de la formule chimique.
Adduct Adduct La valeur de l'adduit est vérifiée et mise au format standard (ex. [M+H]+).
Neutral_mass Precursor_MZ et Adduct La masse neutre mesurée est calculée à partir de la masse du précurseur, à laquelle on ajoute ou retranche la masse de l'adduit (selon le type d'adduit) pour revenir à la masse de la molécule neutre.
MS_level, Ionisation_mode Paramètres choisis à l'étape 1
Num_Peaks Fixé à 0 pour un fichier MS1 ; nombre de fragments du scan pour un fichier MS2

Si une formule est incorrecte ou qu'un adduit ne peut pas être reconnu, un message d'erreur "Cannot compute molecular weight for the following formula(s) : ..." ou "Could not resolve the precursor adduct for the following row(s)/scan(s) : ..." s'affiche. Il faut alors corriger le fichier source (colonne Formula ou Adduct) puis le recharger depuis l'étape 2.

Une fois le calcul terminé, un tableau éditable s'affiche pour une dernière relecture avant intégration. Les colonnes Molecular_weight, Monoisotopic_mass, Adduct, Neutral_mass, MS_level, Ionisation_mode, Num_Peaks, ainsi que Precursor_MZ et Formula, ne sont pas modifiables. L'objectif est de garantir leur cohérence avec les valeurs dont elles sont dérivées. Ces colonnes n'affichent pas l'icône crayon ✎ à côté de leur nom, contrairement aux colonnes éditables. Pour un fichier MS1, les autres colonnes restent modifiables et il est possible de supprimer des lignes. Cependant, pour ajouter des lignes il faut modifier le fichier source et le recharger depuis l'étape 2. Pour un fichier MS2 il n'est possible ni d'ajouter ni de supprimer des lignes.

Le bouton "Validate data" vérifie que les colonnes obligatoires (Lipid_Name, Formula, Precursor_MZ, Adduct) ne contiennent aucune cellule vide. Dans le cas contraire, un message d'avertissement "The table contains empty cells in required columns : ..." s'affiche et il faut compléter le tableau avant de valider à nouveau. Une fois la validation réussie, un résumé apparaît. Il présente le nombre total de lipides ainsi que le nombre de catégories, classes et sous-classes présentes, accompagnés de trois graphiques répartissant les lipides par catégorie, classe et sous-classe.

Pour des modifications non ponctuelles, il est préférable de modifier directement le fichier source afin d'éviter d'introduire des erreurs potentielles.

5ème étape : Insertion des données dans BacLipidDB (Step 5 - Database integration)

Cette dernière étape n'est accessible qu'une fois les données validées à l'étape 4. Un message d'information rappelle le nombre de lipides prêts à être intégrés : "Ready to integrate X lipids into the database." Un clic sur le bouton "Integrate data" déclenche l'insertion des données dans la base BacLipidDB.

Une fois l'intégration terminée avec succès, un message de confirmation "Integration already completed. Use the Reset button in the sidebar to start a new integration." s'affiche, accompagné d'une animation de ballons. Pour intégrer un nouveau fichier, il faut utiliser le bouton "Reset 🔄" de la barre latérale, qui réinitialise l'ensemble du workflow.

Il peut arriver que les données soient correctement enregistrées en base mais qu'une étape suivant l'intégration (sauvegarde automatique de la base ou mise à jour de l'historique) échoue. Dans ce cas, un message d'avertissement s'affiche à la place du message de succès : "Data was integrated successfully, but a post-integration step failed : ...". Il ne faut alors pas recommencer l'intégration (les données sont déjà présentes dans la base) : il suffit d'utiliser le bouton "Reset 🔄" pour démarrer une nouvelle intégration.

Si l'intégration échoue complètement (par exemple en cas de problème avec la base de données elle-même), un message d'erreur "Error during database integration : ..." s'affiche à la place, et aucune donnée n'est enregistrée.

Module 2 : BacLipidDB

La page Database page est un module permettant la visualisation du contenu de la base BacLipidDB. Un sélecteur en haut de page permet de choisir quelle vue afficher.

Sélection d'une table

Le sélecteur "Select a table" propose cinq options :

Detection Contenu brut de la table Detection (un scan/une acquisition par ligne).
Fragment Contenu brut de la table Fragment (fragments MS2).
Lipid Contenu brut de la table Lipid (lipides de référence).
Full view Vue jointe combinant Detection, Lipid et Annotation, colorée par lot d'import, accompagnée de quatre graphiques.
History Historique des imports passés dans la base.

Un encadré "ℹ️ How to use this page", repliable, résume ces cinq options directement sur la page.

Tables brutes : Detection, Fragment, Lipid

Pour ces trois tables, le contenu est affiché tel qu'il est enregistré en base, sans jointure. Le titre du tableau rappelle le nombre de lignes, par exemple "Table : Lipid - 128 rows". Les colonnes numériques suivantes sont affichées avec un nombre de décimales fixe : Precursor_MZ, Neutral_mass, MZ et Intensity (6 décimales), Monoisotopic_mass (8 décimales), RT et CCS (4 décimales), Molecular_weight (0 décimale).

Si la table sélectionnée ne contient aucune ligne, le message "This table contains no data yet." s'affiche à la place du tableau.

Full view

La vue "Full view" combine chaque Annotation avec son Lipid et sa Detection associés, afin de présenter en une seule ligne l'ensemble des informations utiles à la lecture d'un résultat : Lipid_name, Formula, FA_composition, Lipid_class, Lipid_subclass, Lipid_category, Precursor_MZ, Adduct, Neutral_mass, Molecular_weight, Monoisotopic_mass, MS_level, Ionisation_mode, Num_Peaks, RT, CCS, ainsi que Detection_ID comme identifiant.

Chaque ligne est colorée selon le lot d'import (fichier) auquel elle appartient. Une couleur pastel est attribuée à chaque import dans l'ordre où ils ont été intégrés dans Module 1. Sous le tableau un encadré repliable "color caption" rappelle pour chaque import sa couleur, le nom du fichier, sa date d'intégration, son nombre de lignes et le nom de la personne qui l'a intégré.

Une ligne peut apparaître sans couleur de fond si Detection_ID ne correspond à aucun import enregistré dans l'historique. Ce cas ne devrait pas se produire en usage normal. Si cette erreur apparaît, il est important de le signaler à la personne en charge de la maintenance de l'application.

Graphiques (Full view)

Quatre graphiques sont affichés sous le tableau "Full view". Les points ne sont pas colorés lot par lot comme le tableau, mais regroupés en trois catégories : Latest import (le dernier import en date, en rouge), Other imports (les imports précédents, en bleu) et Unknown (lignes sans import connu, en gris).

Measured neutral mass vs. theoretical monoisotopic mass Nuage de points comparant la masse neutre (Neutral_mass, calculée à partir de Precursor_MZ et de l'adduit) à la masse monoisotopique théorique du lipide de référence (Monoisotopic_mass). Une droite pointillée y = x sert de repère visuel : plus un point s'en écarte, plus l'annotation correspondante s'éloigne de la théorie. Le survol d'un point affiche le nom du lipide, sa classe, l'écart en Da et l'erreur en ppm.
Mass error (ppm) vs. precursor neutral mass Même comparaison, mais exprimée en erreur relative (ppm) en fonction de la masse neutre.
Mass error (Da) vs. precursor neutral mass Même comparaison, exprimée cette fois en écart absolu (Da). Ce graphique est suivi d'un tableau "Mass error table" listant chaque annotation avec son nom, sa formule, sa masse neutre, sa masse monoisotopique, l'écart (Da) et l'erreur (ppm), trié par erreur décroissante en valeur absolue, afin de faire ressortir en premier les annotations les plus suspectes.
Van Krevelen diagram (H/C vs O/C) Diagramme classique en chimie des lipides, représentant le ratio hydrogène/carbone en fonction du ratio oxygène/carbone de chaque formule, coloré par classe de lipide (Lipid_class). Les lignes dont la formule ne contient aucun atome de carbone ne sont pas affichées.

Si aucune ligne ne dispose des données nécessaires à un graphique (masse neutre, masse monoisotopique ou formule chimique manquantes), un message d'information s'affiche à la place de ce graphique.

History

La vue "History" liste tous les imports déjà réalisés via le Module 1 : nom du fichier, date d'intégration, niveau MS, mode d'ionisation, nombre de lignes insérées et nom de la personne qui a soumis l'import. Si aucun import n'a encore été effectué, le message "No imports recorded yet." s'affiche à la place du tableau.

En cas d'erreur lors du chargement d'une table (par exemple un problème d'accès à la base de données), le message "Error loading table : ..." s'affiche à la place du contenu attendu.

Module 3 : Export

La page Export est un module permettant de filtrer les annotations présentes dans BacLipidDB puis de les exporter sous différents formats. Un encadré "ℹ️ How to use this page", repliable, résume les trois étapes ci-dessous directement sur la page.

Si la base ne contient aucune donnée, le message "The database contains no data yet." s'affiche à la place de la page. Si le chargement des données échoue (par exemple un problème d'accès à la base de données), le message "Unable to load data from the database: ..." s'affiche à la place.

1ère étape : Filtres (Filters)

Six filtres permettent de restreindre les annotations à exporter. Laisser un filtre vide revient à inclure toutes les valeurs possibles pour ce filtre.

Lipid category Sélection multiple parmi les catégories de lipides présentes en base. Si des lignes n'ont pas de catégorie renseignée, une option (None) apparaît pour les inclure.
Lipid class Sélection multiple parmi les classes de lipides présentes en base, avec la même option (None) si nécessaire.
Lipid subclass Sélection multiple parmi les sous-classes de lipides présentes en base, avec la même option (None) si nécessaire.
MS level Sélection multiple parmi MS1 / MS2.
Ionisation mode Sélection multiple parmi les modes d'ionisation présents en base.
Precursor m/z range Deux champs numériques (Min m/z et Max m/z) pré-remplis avec les valeurs minimale et maximale présentes en base. Seules les annotations dont le Precursor_MZ est compris dans cet intervalle sont incluses dans l'export.

2ème étape : Aperçu (Preview)

Un titre "Preview - N rows" indique le nombre de lignes retenues après application des filtres, suivi d'un tableau d'aperçu reprenant pour chaque annotation son nom, sa formule, son Precursor_MZ, son MS_level, son RT, sa CCS et son Num_Peaks. Si aucune ligne ne correspond aux filtres choisis, le message "No data matches the selected filters." s'affiche à la place du tableau et des boutons de téléchargement.

3ème étape : Téléchargement (Download)

Trois boutons permettent de télécharger les données filtrées, chacun sous un format différent. Le nom du fichier généré inclut toujours la date du jour (YYYYMMDD).

Bouton Contenu Disponibilité
CSV (MS1 + MS2) Toutes les annotations filtrées, colonnes neutral_mass, mz, formula et name, au format CSV compatible avec MZmine. Toujours disponible.
MSP (MS2) Annotations filtrées disposant de spectres de fragments, au format .msp. Chaque entrée contient le nom du lipide, le Precursor_MZ, la masse moléculaire (MW), la masse neutre mesurée (ExactMass), le mode d'ionisation (Ion_mode, P pour positif ou N pour négatif), le RT et la CCS lorsqu'ils sont disponibles, le nombre de fragments (Num Peaks) et la liste des fragments (m/z et intensité). Bouton grisé et non cliquable si aucune annotation MS2 ne figure parmi les lignes filtrées.
CSV (CCS + RT) Annotations filtrées disposant à la fois d'un RT et d'une CCS, colonnes neutral_mass, mz, formula, name, RT et CCS. Bouton grisé si aucune ligne filtrée ne dispose à la fois d'un RT et d'une CCS.

MZmine n'accepte pas un fichier CSV d'annotations MS1 où certaines lignes possèdent des valeurs de CCS/RT et d'autres non. C'est pourquoi l'export CSV (CCS + RT) est proposé séparément de l'export CSV (MS1 + MS2).

Module 4 : Resources

La page Resources sert de guide pour préparer les fichiers d'intégration destinés au Module 1. Elle détaille, pour les niveaux MS1 et MS2, les colonnes attendues avec leur type et leur caractère obligatoire ou optionnel, propose un fichier modèle téléchargeable pour chaque niveau, et permet de consulter et de gérer la liste des adduits acceptés dans la colonne Adduct.

Guide des colonnes MS1

Un tableau récapitule les colonnes attendues dans un fichier d'intégration MS1, avec pour chacune son type et si elle est obligatoire ou non. Seules FA_composition, RT et CCS sont optionnelles (à laisser vides dans le fichier si non disponibles).

Colonne Obligatoire Type Description
Precursor_MZ ✅ float m/z de l'ion mesuré par le spectromètre de masse.
Adduct ✅ text Adduit du précurseur. Détermine le calcul de la masse neutre, indépendamment du mode d'ionisation.
Formula ✅ text Formule chimique brute.
FA_composition ❌ text Composition en acides gras (laisser vide si non disponible).
Lipid_Name ✅ text Identifiant unique du lipide.
Lipid_category ✅ text Catégorie LIPID MAPS.
Lipid_class ✅ text Classe LIPID MAPS.
Lipid_subclass ✅ text Sous-classe LIPID MAPS.
RT ❌ float Temps de rétention en minutes (laisser vide si non disponible).
CCS ❌ float Section efficace de collision en Å² (laisser vide si non disponible).

Les noms de colonnes sont sensibles à la casse : il faut utiliser exactement la capitalisation indiquée dans le tableau ci-dessus. De plus, la formule doit respecter la casse standard des symboles chimiques et ne contenir aucun autre caractère. La formule ne doit pas être écrite sous forme de formule développée.

Modèle MS1

Le bouton "Download MS1 template (.csv)" télécharge le fichier BacLipidDB_MS1_template.csv : une ligne d'exemple illustrant les 7 colonnes obligatoires et laissant vides les 3 colonnes optionnelles (FA_composition, RT, CCS).

Guide des colonnes MS2

Un fichier d'intégration MS2 est organisé en blocs empilés verticalement, un bloc par scan, séparés par une ligne vide. Chaque bloc commence par une ligne Scan #<id>, suivie d'une ligne Label,Value par champ (dans n'importe quel ordre), puis de l'en-tête m/z,Intensity et des lignes de fragments : 

Scan #<id>
Precursor_MZ,<precursor_mz>
Adduct,<adduct>
Formula,<formula>
FA_composition,<fa_composition>
Lipid_Name,<lipid_name>
Lipid_category,<lipid_category>
Lipid_class,<lipid_class>
Lipid_subclass,<lipid_subclass>
Num_peaks,<count>
m/z,Intensity
<mz_1>,<intensity_1>
<mz_2>,<intensity_2>
...

Un tableau récapitule ensuite les colonnes/champs attendus par bloc : Scan #<id>, Precursor_MZ, Adduct, Formula, FA_composition, Lipid_Name, Lipid_category, Lipid_class, Lipid_subclass, Num_peaks, m/z, Intensity, RT et CCS. Seules FA_composition, RT et CCS sont optionnelles : contrairement au MS1, elles doivent être entièrement supprimées du bloc (ligne Label,Value comprise) si non disponibles, au lieu d'être laissées vides. Num_peaks doit correspondre au nombre de lignes m/z/Intensity du bloc.

Les noms de colonnes sont sensibles à la casse. Il faut utiliser exactement la capitalisation indiquée dans le tableau des champs attendus.

Modèle MS2

Le bouton "Download MS2 template (.csv)" télécharge le fichier BacLipidDB_MS2_template.csv : deux scans d'exemple séparés par une ligne vide. Le premier scan inclut les champs optionnels RT et CCS ; le second montre que ces lignes peuvent être omises entièrement quand ces valeurs ne sont pas disponibles.

Adduits

Un tableau liste les adduits acceptés dans la colonne Adduct (intégration MS1 et MS2) : nom de l'adduit, décalage de masse en Da (Mass shift), opération à appliquer au m/z pour obtenir la masse neutre, et un indicateur Custom (✅ pour un adduit ajouté manuellement, ❌ pour un adduit natif de l'application).

Un formulaire "Add a custom adduct" permet d'ajouter un nouvel adduit personnalisé : son nom (ex. [M+Cl]-), son décalage de masse en Da, et son type de formation (Addition, ex. [M+H]+/[M+Na]+, ou Loss, ex. [M-H]-). En cas de succès, le message "Adduct '...' added." s'affiche ; en cas d'erreur (nom vide ou déjà utilisé, décalage non valide...), un message d'erreur détaille le problème rencontré. Les adduits personnalisés sont enregistrés localement et restent disponibles d'une session à l'autre.

Si au moins un adduit personnalisé existe, un sélecteur "Remove a custom adduct" et un bouton "Remove" permettent de le retirer. Les adduits natifs de l'application ne peuvent pas être supprimés.

Module 5 : Management

La page Management permet de corriger ou de supprimer des données déjà intégrées dans BacLipidDB, via deux sections indépendantes : Edit & delete records (édition ou suppression ligne par ligne) et Delete an entire import (suppression en une fois de tout ce qu'un import donné a inséré en base). Un encadré "ℹ️ How to use this page", repliable, résume ces deux sections directement sur la page.

Une sauvegarde de la base est systématiquement effectuée avant toute modification, et chaque action destructrice ou modificatrice doit être confirmée dans une boîte de dialogue dédiée avant d'être appliquée.

Edit & delete records

Le tableau affiche, pour chaque annotation, les colonnes Annotation_ID, Detection_ID, Lipid_ID, Lipid_name, Formula, Lipid_category, Lipid_class, Lipid_subclass, Precursor_MZ, Ionisation_mode, Adduct, Neutral_mass, Molecular_weight, Monoisotopic_mass, MS_level, Num_Peaks, RT et CCS, précédées d'une case à cocher Delete. Si la base ne contient aucune annotation, le message "This table contains no data yet." s'affiche à la place du tableau.

Seules certaines colonnes sont modifiables : Lipid_name, Lipid_category, Lipid_class, Lipid_subclass, Formula, RT et CCS. Les autres (Annotation_ID, Detection_ID, Lipid_ID, Precursor_MZ, Ionisation_mode, Adduct, Neutral_mass, Molecular_weight, Monoisotopic_mass, MS_level et Num_Peaks) sont verrouillées : modifier Precursor_MZ, Ionisation_mode ou Adduct nécessiterait de recalculer Neutral_mass, ce qui n'est pas pris en charge sur cette page ; les autres colonnes verrouillées sont des valeurs calculées ou fixées à l'intégration. Modifier Formula recalcule automatiquement Molecular_weight et Monoisotopic_mass, exactement comme lors de la complétion automatique du Module 1.

Le bouton "Apply changes" vérifie d'abord que Lipid_name, Formula et Precursor_MZ ne sont vides pour aucune ligne non cochée pour suppression ; toute cellule vide ajoute un message d'erreur (une ligne peut donc en cumuler plusieurs) et bloque l'application des changements. Si aucune ligne n'a été modifiée, le message "No changes detected." s'affiche. Sinon, une boîte de dialogue de confirmation résume le nombre de lignes à mettre à jour et à supprimer, avertit que les suppressions sont irréversibles depuis l'application et liste les lignes concernées. Les boutons "Confirm" / "Cancel" permettent respectivement d'appliquer ou d'annuler le plan ; en cas de confirmation, le message "Changes applied." s'affiche une fois la mise à jour terminée.

Supprimer une ligne supprime en base les données liées (Fragment, Annotation, Detection et Lipid) : cette action n'est pas récupérable depuis l'application.

Delete an entire import

Un sélecteur "Select an import to delete" propose la liste des imports déjà réalisés via le Module 1 (nom du fichier, date d'intégration, nombre de lignes insérées et nom de l'intégrateur). Si aucun import n'a encore été effectué, le message "No import history recorded yet." s'affiche à la place.

Une fois un import sélectionné, un encadré rappelle le nombre de lignes enregistrées au moment de l'import ainsi que le nombre de lignes encore présentes en base : les deux valeurs peuvent différer si certaines lignes de ce lot ont déjà été supprimées individuellement via Edit & delete records.

Le bouton "Delete this import" ouvre une boîte de dialogue de confirmation qui avertit du nombre d'enregistrements qui seront supprimés et rappelle qu'une sauvegarde de la base est prise automatiquement. Les boutons "Confirm deletion" / "Cancel" permettent respectivement de supprimer l'import ou d'annuler ; en cas de confirmation, un message "Import nom_du_fichier deleted." s'affiche.
