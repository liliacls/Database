Accueil (Home)

L'application web locale Streamlit BacLipidAPP est développée afin d'interagir de différentes manières avec la base de données relationnelle SQLite BacLipidDB.

Le lancement de l'application permet à l'utilisateur d'arriver sur la page d'accueil (Home). Cette dernière affiche les cinq modules disponibles. Pour accéder à un module, il est possible de cliquer sur son nom dans la barre de navigation latérale à gauche de l'écran, ou directement sur son encadré depuis la page d'accueil.

Les statistiques affichées en dessous présentent le nombre de spectres MS1 et MS2 présents dans la base, ainsi que la taille de BacLipidDB.

Module 1 : Intégration

La page "Integration" est un module permettant l'insertion de données dans BacLipidDB. L'intégration se déroule en cinq étapes. La première étape consiste à la sélection de paramètres qui seront réutilisés plus tard.

1ère étape : Paramétrages (Step 1 - Settings)

La première étape demande à l'utilisateur de choisir le type de spectres qu'il souhaite insérer, ensuite le mode d'acquisition, son identité et enfin le nom du fichier (raw) d'origine des annotations.

Annotation level MS1 / MS2 MS1 pour les annotations comportant uniquement l'ion précurseur, MS2 pour les annotations avec spectres de fragments.
Ionization mode Positive / Negative Mode d'ionisation utilisé lors de l'acquisition. Sert uniquement à remplir la colonne Ionisation_mode en base.
Your name Texte libre Nom de la personne qui intègre ce lot de données, enregistré dans l'historique d'import. À écrire sous la forme "Prénom NOM" (première lettre du prénom en majuscule, un espace, nom de famille entièrement en majuscules).
File row name Texte libre Nom du fichier brut (raw) de l'expérience à l'origine des annotations. Séparer les champs par des "_".

Il est impératif de compléter correctement ces champs afin de maintenir des données cohérentes et traçables dans le temps.

2ème étape : Chargement du fichier (Step 2 - File upload)

La seconde étape est le chargement du fichier. Il faut faire bien attention au format selon si vous avez sélectionné MS1 ou MS2 lors de l'étape 1. Pour un fichier de données MS1 le format attendu est .csv, .tsv ou .xlsx. Pour un fichier de données MS2 le format attendu est .csv ou .tsv. Si un fichier .xlsx est chargé, ce dernier sera rejeté et il faudra le convertir dans l'un des deux formats souhaités.

Le fichier doit répondre en tout point aux modèles du module 4. Il est bien évidemment possible à l'utilisateur de créer lui-même son fichier s'il ne souhaite pas télécharger les modèles (template), cependant l'introduction d'erreur peut nuire à l'intégration des données ensuite. Les points importants à prendre en compte sont le nommage des colonnes, l'écriture des données et les champs obligatoires (cf. Module 4).

Le fichier chargé doit être nommé sous la forme Annotation_MS1/MS2_organisme_appareil. La date du jour n'est pas à inclure dans le nom du fichier, car elle est déjà gérée par l'historique d'import. Par exemple : Annotation_MS1_A.baumannii_MALDI_FTICR.xlsx, Annotation_MS2_A.baumannii_LC_MS.csv.

.csv .tsv .xlsx
Niveau annotation MS1MS2 MS1MS2 MS1
Description Fichier texte simple, valeurs séparées par des virgules. Lisible et modifiable avec un tableur ou un simple éditeur de texte. Fichier texte simple, valeurs séparées par des tabulations. À privilégier si vos données contiennent elles-mêmes des virgules. Fichier Excel natif (format binaire).

Pour un fichier MS1, une fois le fichier déposé, l'application vérifie simplement qu'il peut être lu correctement. Si la lecture réussit, un message de confirmation s'affiche : "File loaded : nom_du_fichier - X rows detected.". Si la lecture échoue, un message d'erreur "Error loading file : ..." s'affiche à la place et il faut corriger le fichier avant de le recharger.

Pour un fichier MS2, ce message ("Error loading file : ...") inclut toujours le détail précis du scan concerné et de la cause de l'erreur. Selon le problème rencontré dans le fichier, le texte affiché est l'un des suivants :

Cause Message affiché
Aucun scan trouvé dans le fichier "Error loading file : No scan found in the file."
Champ obligatoire manquant dans un scan "Error loading file : Missing field(s) for scan 'Scan #2183': Adduct."
Valeur non numérique (Precursor_MZ, Num_peaks, RT ou CCS) "Error loading file : Invalid Precursor_MZ for scan 'Scan #2183': 'abc'."
Aucun fragment trouvé pour un scan "Error loading file : No fragments found for 'Scan #2183'."
Le nombre de fragments ne correspond pas à Num_peaks "Error loading file : 'Num_peaks'=6 does not match the number of fragments found (5) for 'Scan #2183'."

Dans tous les cas, il faut corriger le scan concerné directement dans le fichier source, puis recharger le fichier.

3ème étape : Vérification des colonnes obligatoires (Step 3 - Required columns verification)

Le fichier MS1 est vérifié en 3 étapes successives. Dès qu'une vérification échoue, un message d'erreur s'affiche et vous devez corriger votre fichier puis le recharger avant que la vérification suivante ne s'exécute. Si le fichier est conforme, il s'affiche avec le message "All required columns found".

# Message affiché Cause Comment corriger
1 "The file is missing the following required columns : ..." Une ou plusieurs colonnes obligatoires absentes du fichier Ajouter la/les colonne(s) manquante(s) (voir le guide des colonnes, module Resources)
2 "The file contains empty cells in required columns : ..." Lipid_Name, Formula, Precursor_MZ ou Adduct contient une cellule vide Remplir les cellules vides de ces colonnes
3 "The column Precursor_MZ must contain only numeric values..." Une valeur non numérique dans Precursor_MZ (texte, cellule mal formatée...) Corriger la/les ligne(s) indiquée(s) pour n'avoir que des nombres

Pour un fichier MS2, le fichier ayant déjà été entièrement vérifié à l'étape précédente, cette étape ne fait qu'afficher un récapitulatif : le message "N scan(s) parsed successfully" ainsi qu'un tableau déroulant ("Preview scan data") reprenant le contenu de chaque scan, pour une dernière relecture avant de passer à l'étape suivante.

4ème étape : Complétion automatique et validation (Step 4 - Preview and automatic completion)

Certains champs prévus par le modèle (cf. Module 4) n'ont pas besoin d'être renseignés dans le fichier source car ils peuvent être calculés automatiquement à partir des colonnes Formula, Precursor_MZ et Adduct, ainsi que des paramètres choisis à l'étape 1. Un clic sur le bouton "Run automatic completion" lance ce calcul.

Colonne calculée Calculée à partir de Détails
Molecular_weight Formula La masse moléculaire moyenne est calculée à partir de la formule chimique
Monoisotopic_mass Formula La masse monoisotopique est calculée à partir de la formule chimique
Adduct Adduct La valeur brute de l'adduit est validée et normalisée vers sa forme standard (ex. [M+H]+, insensible à la casse et aux espaces). Lipid_Name n'intervient pas dans ce calcul : il sert uniquement à identifier la ligne/le scan concerné si l'adduit est invalide.
Neutral_mass Precursor_MZ et Adduct La masse neutre est la masse du précurseur auquel on a rajoute ou supprimer la masse de l'adduit afin d'obtenir sa masse monoisotopique neutre
MS_level, Ionisation_mode Paramètres choisis à l'étape 1
Num_Peaks Fixé à 0 pour un fichier MS1 ; nombre de fragments du scan pour un fichier MS2

Si une formule est incorrecte ou qu'un adduit ne peut pas être reconnu, un message d'erreur "Cannot compute molecular weight for the following formula(s) : ..." ou "Could not resolve the precursor adduct for the following row(s)/scan(s) : ..." s'affiche. Il faut alors corriger le fichier source (colonne Formula ou Adduct) puis le recharger depuis l'étape 2.

Une fois le calcul terminé, un tableau éditable s'affiche pour une dernière relecture avant intégration. Les colonnes calculées automatiquement (voir tableau ci-dessus, ainsi que Precursor_MZ et Formula) ne sont pas modifiables, afin de garantir leur cohérence avec les valeurs dont elles sont dérivées : elles n'affichent pas l'icône crayon ✎ à côté de leur nom, contrairement aux colonnes éditables. Pour un fichier MS1, les autres colonnes restent modifiables et il est possible d'ajouter ou de supprimer des lignes. Pour un fichier MS2, le nombre de lignes est fixe (une ligne par scan).

Le bouton "Validate data" vérifie que les colonnes obligatoires (Lipid_Name, Formula, Precursor_MZ, Adduct) ne contiennent aucune cellule vide. Si c'est le cas, un message d'avertissement "The table contains empty cells in required columns : ..." s'affiche et il faut compléter le tableau avant de valider à nouveau. Une fois la validation réussie, un résumé apparaît. Il présente le nombre total de lipides ainsi que le nombre de catégories, classes et sous-classes présentes, accompagnés de trois graphiques répartissant les lipides par catégorie, classe et sous-classe.

Pour des modifications non ponctuelles il est préférable de privilégier une modification du fichier afin d'éviter d'introduire des erreurs potentielles.

5ème étape : Insertion des données dans BacLipidDB (Step 5 - Database integration)

Cette dernière étape n'est accessible qu'une fois les données validées à l'étape 4. Un message d'information rappelle le nombre de lipides prêts à être intégrés : "Ready to integrate X lipids into the database." Un clic sur le bouton "Integrate data" déclenche l'insertion des données dans la base BacLipidDB (tables Detection, Lipid, Annotation, et Fragment pour les fichiers MS2).

Une fois l'intégration terminée avec succès, un message de confirmation "Integration already completed. Use the Reset button in the sidebar to start a new integration." s'affiche, accompagné d'une animation de ballons. Pour intégrer un nouveau fichier, il faut utiliser le bouton "Reset 🔄" de la barre latérale, qui réinitialise l'ensemble du workflow.

Il peut arriver que les données soient correctement enregistrées en base mais qu'une étape suivant l'intégration (sauvegarde automatique de la base ou mise à jour de l'historique) échoue. Dans ce cas, un message d'avertissement s'affiche à la place du message de succès : Data was integrated successfully, but a post-integration step failed : ...". Il ne faut alors pas recommencer l'intégration (les données sont déjà présentes dans la base) : il suffit d'utiliser le bouton "Reset 🔄" pour démarrer une nouvelle intégration.

Si l'intégration échoue complètement (par exemple en cas de problème avec la base de données elle-même), un message d'erreur "Error during database integration : ..." s'affiche à la place, et aucune donnée n'est enregistrée.

Module 2 : BacLipidDB

La page "BacLipidDB" est un module permettant la visualisation du contenu de la base BacLipidDB. Un sélecteur en haut de page permet de choisir quelle vue afficher.

Sélection d'une table

Le sélecteur "Select a table" propose cinq options :

Detection Contenu brut de la table Detection (un scan/une acquisition par ligne).
Fragment Contenu brut de la table Fragment (fragments MS2).
Lipid Contenu brut de la table Lipid (lipides de référence).
Full view Vue jointe combinant Detection, Lipid et Annotation, colorée par lot d'import, accompagnée de quatre graphiques.
History Historique des imports passés dans la base.

Un encadré "ℹ️ How to use this page", repliable, résume ces cinq options directement sur la page.

Tables brutes : Detection, Fragment, Lipid

Pour ces trois tables, le contenu est affiché tel qu'il est enregistré en base, sans jointure. Le titre du tableau rappelle le nombre de lignes, par exemple "Table : Lipid - 128 rows". Les colonnes numériques suivantes sont affichées avec un nombre de décimales fixe : Precursor_MZ, Neutral_mass, MZ, Monoisotopic_mass et Intensity (6 décimales), RT et CCS (4 décimales), Molecular_weight (0 décimale).

Si la table sélectionnée ne contient aucune ligne, le message "This table contains no data yet." s'affiche à la place du tableau.

Full view

La vue "Full view" combine chaque Annotation avec son Lipid et sa Detection associés, afin de présenter en une seule ligne l'ensemble des informations utiles à la lecture d'un résultat : Lipid_name, Formula, FA_composition, Lipid_class, Lipid_subclass, Lipid_category, Precursor_MZ, Adduct, Neutral_mass, Molecular_weight, Monoisotopic_mass, MS_level, Ionisation_mode, Num_Peaks, RT, CCS, ainsi que Detection_ID comme identifiant.

Chaque ligne est colorée selon le lot d'import (fichier) auquel elle appartient : une couleur pastel distincte est attribuée à chaque import, dans l'ordre où ils ont été intégrés dans Module 1. Sous le tableau un encadré repliable "color caption" rappelle pour chaque import sa couleur, le nom du fichier, sa date d'intégration, son nombre de lignes et le nom de la personne qui l'a intégré.

Une ligne peut apparaître sans couleur de fond si Detection_ID ne correspond à aucun import enregistré dans l'historique. Ce cas ne devrait pas se produire en usage normal. Si cette erreur apparait il est important de le signaler à la personne en charge de la maintenance de l'application.

Graphiques (Full view)

Quatre graphiques sont affichés sous le tableau "Full view". Les points ne sont pas colorés lot par lot comme le tableau, mais regroupés en trois catégories : Latest import (le dernier import en date, en rouge), Other imports (les imports précédents, en bleu) et Unknown (lignes sans import connu, en gris).

Measured neutral mass vs. theoretical monoisotopic mass Nuage de points comparant la masse neutre mesurée (Neutral_mass, calculée à partir de Precursor_MZ et de l'adduit) à la masse monoisotopique théorique du lipide de référence (Monoisotopic_mass). Une droite pointillée y = x sert de repère visuel : plus un point s'en écarte, plus l'annotation correspondante s'éloigne de la théorie. Le survol d'un point affiche le nom du lipide, sa classe, l'écart en Da et l'erreur en ppm.
Mass error (ppm) vs. precursor neutral mass Même comparaison, mais exprimée en erreur relative (ppm) en fonction de la masse neutre.
Mass error (Da) vs. precursor neutral mass Même comparaison, exprimée cette fois en écart absolu (Da). Ce graphique est suivi d'un tableau "Mass error table" listant chaque annotation avec son nom, sa formule, sa masse neutre, sa masse monoisotopique, l'écart (Da) et l'erreur (ppm), trié par erreur décroissante en valeur absolue, afin de faire ressortir en premier les annotations les plus suspectes.
Van Krevelen diagram (H/C vs O/C) Diagramme classique en chimie des lipides, représentant le ratio hydrogène/carbone en fonction du ratio oxygène/carbone de chaque formule, coloré par classe de lipide (Lipid_class). Les lignes dont la formule ne contient aucun atome de carbone ne sont pas affichées.

Si aucune ligne ne dispose des données nécessaires à un graphique (masse neutre, masse monoisotopique ou formule chimique manquantes), un message d'information s'affiche à la place de ce graphique.

History

La vue "History" liste tous les imports déjà réalisés via le Module 1 : nom du fichier, date d'intégration, niveau MS, mode d'ionisation, nombre de lignes insérées et nom de la personne qui a soumis l'import. Si aucun import n'a encore été effectué, le message "No imports recorded yet." s'affiche à la place du tableau.

En cas d'erreur lors du chargement d'une table (par exemple un problème d'accès à la base de données), le message "Error loading table : ..." s'affiche à la place du contenu attendu.
